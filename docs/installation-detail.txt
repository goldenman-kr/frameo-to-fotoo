Frameo → Fotoo 전환: DP103용 최종 설치 루틴
정리 기준: 2026-10-29 / 실제 사용한 파일과 확인된 최종 구성

1. 순정 Frameo에서 ADB 액세스를 켠다

다른 앱을 설치하기 전에, 액자의 순정 Frameo 앱에서 먼저 ADB 접근을 허용한다.
이 단계는 PC가 아니라 액자 화면에서 진행한다.

  ① Frameo가 표시된 액자 화면을 터치한다.
  ② 화면을 터치하면 보이는 "설정"을 누른다.
  ③ 설정에서 "소개"로 들어간다.
  ④ "ADB 액세스"를 켠다.

메뉴 경로:
  Frameo 앱 → 화면 터치 → 설정 → 소개 → ADB 액세스 (켜기)

위 절차를 완료하면 USB 케이블 연결을 통해 PC에서 adb로 접근할 수 있다.
이후 아래 순서에 따라 파일을 준비하고, 안정적인 외부 전원과 데이터 USB를
연결한 뒤 PC에서 ADB 인식을 확인하여 나머지 설치 절차를 수행한다.
PC 연결 승인 창이 표시되는 경우에는 액자에서 연결을 승인한다.

적용 대상과 완료 기준

대상: DP103 / Rockchip RK3126C / Android 6.0.1(API 23) / ARM 32비트(armeabi-v7a)
현재 대상 ADB serial: YOUR_DEVICE_SERIAL

기존 Android와 패널 드라이버를 유지하고, Fotoo + Nova Launcher + Floating Home으로
사용 환경을 바꾸는 방식이다. OS 교체나 펌웨어 플래싱은 이 과정에 포함되지 않는다.
기존 Frameo 패키지 net.frameo.frame은 삭제하지 않고 보존했다.

확인된 최종 구성:
- Fotoo 2.6.5: 설치·실행, 사용자 사진 액자 용도로 사용
- Nova Launcher 6.2.19: 기본 홈으로 사용
- Floating Home 1.4: 홈·뒤로가기 오버레이
- Google 계정 로그인과 Fotoo 프리미엄 복구: 사용자 확인 완료
- Google 시스템 앱 추가 후 정상 재부팅: 확인
- Floating Home 최신 버전 실제 재부팅 자동 시작: 미시험
  (앱에 지정한 BOOT_COMPLETED 수신·자동 시작 로그는 확인)

이 저장소은 위 단말의 확인된 구성이다. 다른 Android 버전, 64비트 기기,
다른 보드나 파티션 구성에 Google 시스템 파일을 그대로 적용하지 않는다.

2. 파일을 준비한다

저장소를 git clone한 뒤, 저장소 루트를 현재 작업 디렉터리로 삼는다.

필수 앱:
- apps/nova/Nova-6.2.19.apk
- apps/floating-home/FloatingHome-1.4.apk
- apps/fotoo-2.6.5-armv7/ 아래 APK 5개
  com.bo.fotoo.apk                 앱 본체
  config.armeabi_v7a.apk           ARMv7 네이티브 구성
  config.en.apk                   영어 리소스
  config.ko.apk                   한국어 리소스
  config.xxhdpi.apk               화면 밀도 리소스

Fotoo는 분할 APK이므로 본체만 설치하지 않고 5개를 한 번에 설치한다.
APK 파일명에 armv7이 없더라도 이 폴더의 config.armeabi_v7a.apk가 필요하다.

Google 계정과 구매 복원을 위한 구성:
- google/system-stage/GoogleServicesFramework/GoogleServicesFramework.apk
  Google Services Framework 6.0.1
- google/system-stage/GoogleLoginService/GoogleLoginService.apk
  Google Account Manager 6.0.1
- google/system-stage/PrebuiltGmsCore/PrebuiltGmsCore.apk + lib/arm/
  Google Play services 21.48.57 (040300-424705839)
- google/system-stage/Phonesky/Phonesky.apk + lib/arm/
  Google Play Store 29.2.15-21 [0] [PR] 426536134
- google/apply-system-google.sh: 위 4개 폴더를 추가하는 단말 전용 작업 스크립트
- google/system-stage-manifest.json: 네이티브 라이브러리를 포함한 32개 파일의 해시

도구:
- tools/macos/adb: 이 Mac에서 사용한 ADB 실행 파일(Apple Silicon / Intel)
- tools/macos/NOTICE.txt 및 source.properties: 도구 고지와 버전 정보
- 다른 OS에서는 그 OS의 Android SDK Platform-Tools가 별도로 필요하다.

보조 자료:
- apps/floating-home/source/: 직접 만든 버튼 앱 소스와 빌드 설명
- docs/: 최종 구성 정보, 설치 검증 자료
- FILES.csv: 전체 파일 용도·크기·SHA-256
- SHA256SUMS.txt: 묶음 내 파일 무결성 확인

3. 안정적인 전원과 데이터 USB를 연결한다

이 단말은 안정적인 외부 전원을 공급한 뒤 정상 부팅했다.
정격·극성이 맞는 정상 전원 어댑터와 데이터 전송 가능한 USB 케이블을 사용한다.
USB만으로 전원이 충분하다고 가정하지 않는다.
1단계에서 Frameo의 "ADB 액세스"를 켠 상태여야 한다.
필요한 경우 단말에서 컴퓨터 연결을 승인한다.

macOS 터미널에서:

  ADB="$PWD/tools/macos/adb"
  SERIAL=YOUR_DEVICE_SERIAL
  "$ADB" devices -l
  "$ADB" -s "$SERIAL" shell getprop ro.product.model
  "$ADB" -s "$SERIAL" shell getprop ro.build.version.release
  "$ADB" -s "$SERIAL" shell getprop ro.product.cpu.abi

목록에서 대상이 device 상태인지 확인한다.
다른 액자에서는 SERIAL을 해당 기기의 값으로 바꾼다.
여러 ADB 기기가 있으면 -s를 생략하지 않는다.

4. Nova와 Floating Home을 설치하고 조작 통로를 먼저 확보한다

  "$ADB" -s "$SERIAL" install -r apps/nova/Nova-6.2.19.apk
  "$ADB" -s "$SERIAL" install -r apps/floating-home/FloatingHome-1.4.apk
  "$ADB" -s "$SERIAL" shell am start -n local.frame.floatinghome/.MainActivity

Floating Home에서 '홈 버튼 켜기 / 표시 권한 허용'을 누르고 다른 앱 위에 표시를 허용한다.
이 단말에서 이미 가능한 su를 뒤로가기 기능에 사용한다. 새로 루팅하는 과정은 없다.
홈 버튼을 눌러 홈 선택창이 뜨면 Nova Launcher를 선택하고 '항상'으로 지정한다.
선택창이 뜨지 않으면 Android 설정의 기본 홈 앱 선택에서 Nova를 지정한다.
현재 사용한 버전은 Nova 6.2.19이다.

Floating Home 사용법:
- 알약 왼쪽 절반: 홈 / 오른쪽 절반: 뒤로가기
- 각 절반의 터치 영역: 56×56dp / 전체: 112×56dp
- 배경색 #334658, 전체 불투명도 25%, 외부 테두리 없음
- 어느 쪽이든 드래그 후 놓으면 해당 사분면의 모서리로 이동
- 회전 후에도 같은 모서리 유지
- 앱에서 켠 상태이면 부팅 완료 후 자동 시작하도록 구성
- 앱의 '홈 버튼 끄기'는 자동 시작도 끔

Nova의 앱 목록에서 Android 설정에 들어갈 수 있는지 먼저 확인한다.
이 구성을 사용하면 PC 없이 Fotoo와 설정 사이를 이동할 수 있다.

5. Fotoo를 분할 APK 세트로 설치한다

  "$ADB" -s "$SERIAL" install-multiple -r \
    apps/fotoo-2.6.5-armv7/com.bo.fotoo.apk \
    apps/fotoo-2.6.5-armv7/config.armeabi_v7a.apk \
    apps/fotoo-2.6.5-armv7/config.en.apk \
    apps/fotoo-2.6.5-armv7/config.ko.apk \
    apps/fotoo-2.6.5-armv7/config.xxhdpi.apk

Nova 앱 목록에서 Fotoo를 실행하고 필요한 사진·저장소 권한을 허용한다.
PC에서 초기 실행이 필요하면:

  "$ADB" -s "$SERIAL" shell am start -n \
    com.bo.fotoo/com.bo.fotoo.ui.splash.FTSplashActivity

사진 추가와 Google Play 구매 계정 연동은 별개의 설정이다.
프리미엄 구매 복원에는 Google Play 쪽의 구매 계정이 필요하다.

참고: install-apps.command는 4~5단계의 APK 설치만 수행한다.
권한 승인, 기본 홈 선택, 로그인은 단말에서 직접 진행한다.
Google 시스템 변경·재부팅·앱 삭제는 이 도우미가 수행하지 않는다.
이미 최종 구성이 완료된 현재 단말에 다시 실행할 필요는 없다.

6. Google 시스템 추가 전에 백업과 복구 경로를 확보한다

일반 앱 설치만으로 이 단말에 필요한 Google 시스템 권한을 충족한다고 가정하지 않는다.
Google 구성 단계는 /system/priv-app에 파일을 추가하므로 먼저 백업이 필요하다.

이미 확보한 이 단말 전용 백업은 원래 작업 머신에 별도 보관한:
  DP103-pre-google-backup/

이 단말 전용 백업은 GitHub에 올리지 않았다. 다른 기기에서는 자체 백업을 확보한다.

이 백업은 Google 시스템 통합 직전 상태이며, 공장 초기 펌웨어 전체가 아니다.
당시 설치된 일반 앱과 사용자 데이터의 전체 백업도 아니다.

보존한 이미지 9개:
  reserved-prefix.img, uboot.img, resource.img, kernel.img, boot.img,
  recovery.img, backup.img, radical_update.img, system.img

manifest.json의 크기·주소·verified와 SHA256SUMS.txt를 함께 보존한다.
사용자 사진, 계정, userdata, cache, metadata, kpanic, misc는 포함하지 않았다.
새 단말에 적용한다면 그 단말 자체의 새 백업과 복구 경로 확인이 필요하다.
이 액자의 이미지를 다른 기기에 쓰지 않는다.

확인된 복구 경로 범위:
- Rockchip Loader USB 2207:310d 진입, 저장장치 조회와 일부 LBA 읽기
- Loader에서 정상 Android로 돌아오기
- 이 단말의 Loader LBA = Linux 물리 sector - 8192

물리 버튼만으로 부팅 불능 상태에서 Loader에 진입하는 방법과
이미지 실제 복원 쓰기는 검증하지 않았다. 백업만으로 복구가 보장되지는 않는다.
백업 파일을 실행 중인 마운트된 /system에 덮어쓰지 않는다.

7. Google 시스템 구성 4개를 추가한다 — 해당 기능이 없는 동일 구성 단말에만

현재 단말은 이 단계가 완료되어 있으며 Google 로그인과 프리미엄 복구도 확인했다.
이미 설치된 단말에는 이 단계를 반복하지 않는다.

기존 su 권한과 백업·복구 준비를 확인한 뒤 수행하는 시스템 변경 단계다.
아래 명령을 나열한 것은 재실행 지시가 아니라 재현을 위한 작업 절차다.

  "$ADB" -s "$SERIAL" shell su -c id

uid=0인지 확인하고, /system 여유 공간과 기존 Google 앱 구성도 확인한다.
현재 파일 세트는 APK와 ARM 라이브러리를 합쳐 약 173MiB이다.
새 파일과 작업 공간을 위한 충분한 여유가 필요하다.

google/system-stage/의 전체 구조를 다음 단말 경로에 배치한다:
  /data/local/tmp/dp103-google-system-stage/

  "$ADB" -s "$SERIAL" shell mkdir -p /data/local/tmp/dp103-google-system-stage
  "$ADB" -s "$SERIAL" push google/system-stage/. /data/local/tmp/dp103-google-system-stage/
  "$ADB" -s "$SERIAL" push google/apply-system-google.sh /data/local/tmp/dp103-add-google-system.sh
  "$ADB" -s "$SERIAL" shell "su -c 'sh /data/local/tmp/dp103-add-google-system.sh'"

성공 표식:
  SYSTEM_GOOGLE_FILES_VERIFIED_32

스크립트는 기존 Google 디렉터리가 없는 경우만 진행한다.
4개 새 폴더와 필요한 lib/arm 파일을 /system/priv-app에 추가하고,
디렉터리 0755 / 파일 0644 / 소유자 root:root / SELinux 라벨을 맞춘다.
기존 시스템 파일·커널·부트로더는 덮어쓰지 않는다.
원본과 파일 해시를 대조하고 /system을 읽기 전용으로 되돌린다.
시스템 변경은 부팅 실패 가능성이 있으므로 6단계가 선행되어야 한다.

Google 시스템 통합을 적용하려면 별도로 통제된 정상 재부팅이 필요하다.
묶음의 도우미와 Google 스크립트는 재부팅을 자동 실행하지 않는다.
이미 완료된 현재 단말을 이 문서를 읽는 과정에서 재부팅할 필요는 없다.

8. Google 인식 상태를 확인하고 구매 계정으로 로그인한다

시스템 통합 적용 후 정상 부팅과 ADB 복귀를 확인한다.
4개 패키지가 활성화되어 있어야 한다:
  com.google.android.gsf
  com.google.android.gsf.login
  com.google.android.gms
  com.android.vending

기존에 비활성화한 패키지만 pm enable로 활성화한다.
Google Services Framework가 privileged 시스템 앱으로 인식되고
MANAGE_USERS 권한이 부여되었는지 확인한다. 권한을 임의 우회하지 않는다.

Nova에서 Google Play 스토어를 실행한다.
Fotoo 프리미엄을 실제 구매한 Google 계정으로 사용자가 직접 로그인한다.
로그인 정보·비밀번호·토큰을 PC로 추출하거나 파일 묶음에 보관하지 않는다.

9. Fotoo 프리미엄을 복원하고 일상 사용을 설정한다

Fotoo를 실행하고 구매 복원 기능을 이용해 프리미엄 상태를 확인한다.
이 단말에서는 Google Play 계정 로그인과 Fotoo 프리미엄 복구가
사용자에 의해 완료되었음을 확인했다.

원하는 사진 소스, 전환 간격, 화면 방향 등은 Fotoo에서 설정한다.
Nova에 Fotoo와 Android 설정 아이콘을 배치하면 접근하기 쉽다.
홈 버튼으로 Nova로 나가 설정을 변경하고 다시 Fotoo를 실행한다.
이 구성은 Fotoo를 기본 홈 앱으로 강제 지정하지 않는다.
Fotoo 자동 실행이나 장시간 표시·절전 설정은 실제 단말의 앱 설정에서 별도 확인한다.

10. 최종 확인 및 보관

확인 목록:
[ ] 안정적인 어댑터에서 부팅·표시·터치가 정상이다.
[ ] 홈 버튼을 누르면 Nova가 열린다.
[ ] Nova에서 Android 설정과 Fotoo를 실행할 수 있다.
[ ] Fotoo 위에서 홈·뒤로가기가 동작한다.
[ ] 알약을 끌어 네 모서리로 이동할 수 있다.
[ ] Google Play가 구매 계정으로 로그인되어 있다.
[ ] Fotoo가 프리미엄을 인식한다.
[ ] 다음 정상 재부팅 때 Floating Home 자동 표시 여부를 별도 확인한다.

현재 작업에서 OS 교체·공장 초기화·부트로더 해제·새 루팅은 하지 않았다.
이전 대체 런처나 별도 내비게이션 앱은 최종 설치 루틴에 필요하지 않다.
기존 Frameo 삭제도 최종 구성의 필수 단계가 아니다.

보관:

- 별도 DP103-pre-google-backup 폴더 전체
- Floating Home을 같은 서명으로 나중에 업데이트하려면 기존 로컬 서명 키 보존
  원래 작업 폴더: work/floating-home-build/local-signing.p12
